# MIMOSA 1.5.0

_Status: in development_

This page records completed changes as the model-construction migration progresses.
Model construction now builds a Pyomo ConcreteModel directly. Model equations and the normal
MIMOSA entry point are unchanged.

## Removed custom parameter mappings

`custom_constraints.custom_mapping` has been removed from the configuration schema and
model instantiation. Remove this key from existing configuration dictionaries or YAML files;
supplying it now raises the normal obsolete-configuration error, including for empty mappings.

`custom_constraints.constraint_variables` and `custom_constraints.disabled_constraints`
remain supported, including prescribed trajectories and constraint deactivation. Normal
configuration values and regional input overrides under `params["regions"]` also remain supported.

## Parameters with source metadata

`Param` imported from `mimosa.common` is now a factory returning a native Pyomo parameter.
Existing parameter declarations continue to accept ordinary Pyomo arguments. The factory
also accepts a `SourcedValue` initializer carrying resolved values and a documentation key:

```python
from mimosa.common import ConcreteModel, Param, SourcedValue

m = ConcreteModel()
m.alpha = Param(initialize=SourcedValue(0.3, "::economics.GDP.alpha"))
```

The factory passes `0.3` to Pyomo and sets `m.alpha.doc` to `"::economics.GDP.alpha"`.
This preserves the source metadata used by the existing parameter-documentation hook.
`SourcedValue` does not load configuration or data, or perform unit conversion.
Supplying an explicit `doc` together with sourced initialization raises `ValueError`.

## Explicit input lookup

`mimosa.core.model_inputs.ModelInputs` provides sourced configuration, regional and time/region
lookups through `config`, `regional`, `time_regional` and `time_config`. `config_value` returns plain configuration
values or sections for Python choices. The lookup object reuses prepared configuration and existing
stores, including quantity conversion, regional overrides, interpolation and time-grid validation.
`time_config(path)` interpolates numeric calendar-year keyframes into timestep-indexed values,
preserving source metadata. Components choose their own configuration path, including SSP selection
for mitigation; the lookup class has no MAC-specific method.

The initial conversion checkpoints used `get_constraints(m, context)`, with prepared input lookup
supplied as `context.inputs`, reusing the existing configuration and data stores. The default
`welfare_loss_minimising` component is the first migrated component: it initializes `elasmu` through
`context.inputs.config("economics.elasmu")`. Its equations and documentation marker are unchanged.
These input-conversion checkpoints initially retained abstract construction and instantiation.

The Cobb–Douglas economic component now also initializes its regional capital-stock coefficient
and the `alpha`, `dk`, `sr` and `ignore_damages` parameters through input lookup. Existing regional
overrides, unit metadata, capital initialization, TFP calibration and equations are preserved.

Emissions and mitigation now also initialize configured parameters through input lookup.
Mitigation selects its regional calibration column and SSP keyframe path locally and declares
`MAC_SSP_calibration_factor`, previously declared in the base model. That parameter now carries
its configuration source in `doc`; its values and units are unchanged. Sea-level rise reads its
projection option through `config_value`.

The emissions component validates a nonzero pulse against the initialized model's calendar grid
using the standard Pyomo `Param(validate=...)` callback. A nonzero off-grid pulse still raises
`ValueError`; zero off-grid pulses remain allowed. The duplicate checks in input lookup and
instantiation have been removed. This works for both abstract and concrete construction.

COACCH now initializes its damage scale and regional coefficients through input lookup.
Its component chooses combined or separate damages, adaptation and quantile sources directly;
the COACCH-specific instantiator override has been removed. Combined mode requests only the
combined coefficient columns and initializes the unused SLR parameters to their existing
fixed values. Source metadata now identifies the combined columns actually used; fixed
placeholder values have no source label. Numerical damage behavior and regional overrides
are unchanged.

ACCREU now initializes its sectoral damage, adaptation and mortality parameters through
explicit input lookup. Adaptation and mortality component options come from `config_value`;
the existing adaptation calibration helpers and mathematical rules are retained. Regional
overrides, currency conversion, mortality bounds, adaptation delays, and joint/sequential
solve behavior are preserved. ACCREU_CGE selects its quantile columns locally, retaining
the existing two-decimal column-name formatting.

ACCREU's internal sector helpers accept `inputs: ModelInputs` alongside the model and
adaptation options. `get_adaptation_options` also receives inputs directly.

The remaining welfare variants, both objectives, per-capita convergence, equal cumulative
per-capita effort sharing and global cost-pool payment limits now use explicit input lookup.
The redundant code default for `percapconv_year` has been removed; the default still comes
from `config_default.yaml`. Derived shares, historical-debt calculations, repayment rules
and objective discounting are unchanged. Components now have no doc-only sourced parameter
declarations; shared base inputs are also initialized explicitly by the concrete builder.

## Direct concrete construction

`mimosa/model_builder.py` replaces `mimosa/abstract_model.py`. Its `create_model(inputs)`
function calls components explicitly on an initialized ConcreteModel. The base
model receives prepared `ModelInputs`, including its calendar grid, regions, baseline data and
regional currency conversion coefficients. `beginyear` now carries the `::time.start` source key.
Component type hints use `ConcreteModel`; useful `ModelInputs` hints use ordinary imports.

The preprocessor no longer builds/clones an abstract model or scans parameter `doc` strings to
load values. `InstantiatedModel` and its manual MAC mapping have been removed, as have
`Preprocessor._abstract_model`, `instantiated_model` and the private instantiation stage.
`doc` retains its documentation role. Initialize parameters explicitly; a doc-only parameter
declaration no longer supplies input values.

Construction still attaches collected constraints after all component declarations. Prescribed
trajectories and disabled constraints are then applied before the existing Pyomo transformations
and initial-abatement fixing. Simulation preparation, preruns, no-policy baselines, and the
three-value `ModelBuildResult` unpacking contract are preserved.

## Component construction and module selection

The global component catalogue and `mimosa.core.component_definition` have been removed.
`create_model` calls each component's `get_constraints(m, inputs)` explicitly in the existing
construction order. Selectable packages (damages, emission trading, financial transfers,
effort sharing, welfare and objective) read their own module selector through `inputs.config_value`
and use their existing selection dictionaries. Module choices and unknown-module errors are unchanged.
The objective still returns its Pyomo objective together with any additional constraints.

To add a component, import it and add a construction call in `mimosa/model_builder.py`.
To add a variant, extend the relevant package's selection dictionary and configuration enum.
Extensions using `MODEL_COMPONENTS`, `ALL_COMPONENTS`, `OBJECTIVE_COMPONENT` or
`ComponentDefinition` should use these direct construction and package entry points instead.

## Direct input interface

Component entry points now use `get_constraints(m: ConcreteModel, inputs: ModelInputs)`.
They initialize parameters through `inputs.config`, `inputs.regional` and `inputs.time_regional`,
and read construction options through `inputs.config_value`. Defaults come from the validated
configuration rather than being repeated in component helpers.

`ModelContext`, `ComponentConfig`, `mimosa.core.helpers` and their common exports have been removed.
`MIMOSA.inputs` and `ModelBuildResult.inputs` replace their former context attributes; tuple
unpacking still yields the model, parsed parameters and equations. Extensions should accept
`inputs` directly. Module names, config keys, parameter metadata, ACCREU workflow checks and
the ordinary MIMOSA construction/run interface are unchanged.

## Compatibility for model extensions

### Configuration option locations

Options now live beside their related scientific parameters. The ACCREU section remains flat,
alongside the existing mortality valuation, effectiveness scale and adaptation delay parameters.
Module selectors stay under `model structure`. Defaults and supported values are unchanged.

| Former path | New path |
| --- | --- |
| `model structure.damage module options.ACCREU_adaptation` | `economics.damages.accreu.adaptation` |
| `model structure.damage module options.ACCREU_CBA_strategy` | `economics.damages.accreu.cba_strategy` |
| `model structure.damage module options.ACCREU_adaptation_determination` | `economics.damages.accreu.adaptation_determination` |
| `model structure.damage module options.ACCREU_adaptation_calibration` | `economics.damages.accreu.adaptation_calibration` |
| `model structure.damage module options.ACCREU_monetise_mortality` | `economics.damages.accreu.monetise_mortality` |
| `model structure.sealevelrise options.projection` | `sealevelrise.projection` |

Update existing configuration dictionaries and YAML files to these paths. Old paths raise the
normal obsolete-configuration error; they are not silently ignored or automatically translated.

### Native parameter type

Use `PyomoParam` for component filtering, type checks and type annotations:

```python
from mimosa.common import PyomoParam

parameters = list(m.component_objects(PyomoParam))
```

Continue using `Param(...)` to declare parameters. It is a factory rather than a class,
so `isinstance(parameter, Param)` must be replaced with `isinstance(parameter, PyomoParam)`.
The constructed components themselves remain ordinary Pyomo parameters.

See [Adding parameters and data](../extending/parameters.md) for the declaration conventions.
